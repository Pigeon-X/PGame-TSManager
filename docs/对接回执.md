## 插件热升级：实测证据链（2026-10-08）

1. 加载器是影子加载：`TerrariaServer.dll::ServerApi.LoadPlugins` 与 `HotReload.Core::LoadPluginFromDisk` 均用 `Assembly.Load(byte[], byte[])`。
2. 运行中的沙箱 `ServerPlugins\*.dll` **独占打开成功**、覆盖拷贝成功 → 文件未被锁。
3. `/hr load` 会重新读盘：沙箱 DLL 换成坏字节 → 报 `Bad IL format`；换回好文件 → 正常加载。
4. 端到端：破坏沙箱 DLL → `POST .../syncplugins` → 沙箱 SHA 立即恢复为总库版本 → `/hr load` 成功（**服务器未重启**）。

⇒ 插件升级流程：**总库 `Plugins\` 放新 DLL → `POST /tsm/servers/{id}/syncplugins` → `/hr load <插件>`**，无需重启。

## Seq 单调修复 + Bot 最终复验（commit `099c423` / Bot `2657f1b`）

背景缺陷（Bot 报）：TSM `Seq` 每次进程启动从 1 重计，客户端把 seq 落盘做去重基线 → 重启后新事件 `Seq ≤ 基线` 被**静默丢弃**（`world.rebuild.*`、`server.process.conflict` 都曾因此漏收）。

修复：

- `ControlEventHub` 静态构造用**毫秒时间戳做 seq 下界** → 跨进程重启严格单调。
- `/tsm/status` 新增 `managerStartedAt`、`eventEpoch`（识别 TSM 是否重启）。
- `/tsm/servers` 每项新增 `rebuilding`；**停机服 `pid` 为 `null`**（文档标注）。
- `POST /tsm/world/rebuild` 并发保护：同服已在重建 → **409 `rebuild_in_progress`**。

实测（2026-10-08 23:44）：

- 重启前 max seq = 32 → 重启后 min seq = **1791474293234**（单调成立，且 ≥ eventEpoch）。
- `/tsm/status` 返回 `managerStartedAt=2026-10-08T23:44:51.93…`、`eventEpoch=1791474293233`。
- 停机流光城 → `/tsm/servers` 该项 `"pid": null`；`rebuilding=false`。

Bot 最终复验（提交 `2657f1b`）：

- `server.process.conflict`（假进程 pid 7024）已收到并即时播报；进程未被清理。
- `world.rebuild.*`（started→backup_created→generating）已收到。
- `Last-Event-ID` 快路径恢复：`从 seq 1791474293257 续传，断线期间事件会补发`，3ms 建连。
- `managerStartedAt`/`eventEpoch` 已接入日志；`rebuilding`/409 已适配（`/tsm 服务区` 显示「正在重建世界」）。
- Bot 额外防御：发现 seq 回退时按「新纪元」重置基线并照常处理，不静默丢事件。
- Bot 侧**无待办**；真建 rebuild 仍保留本地闸（默认关），等维护窗口。
