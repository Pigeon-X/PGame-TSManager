## ② 内存：结论 + 限制（**无法从 TSM 侧强制回落**）

**实测**（独立沙箱，只留 TShockAPI，零第三方插件）：

| 加载的世界 | Private |
|---|---|
| 流光城的图（8400×2400） | 1048 MB |
| 泰拉大陆的图（8400×2400） | 1036 MB |

⇒ **约 1.0GB 是「大世界加载后的启动峰值」**，与插件无关，也不是泄漏。

**回落证据**：直播服重建世界后（重建过程必然触发大量分配 → gen2 GC）：
**Private 1036MB → 594MB**，与长期运行的泰拉/神域（536–556MB）同量级。

⇒ **空闲服**因为几乎不分配对象、gen2 GC 长期不触发，会**长时间停在峰值**（流光城 1096MB 就是这种状态）。

**限制**：`GC.Collect` 必须在**目标进程内**执行；管理器跨进程只能调 `EmptyWorkingSet`（只影响工作集，动不了 Private）。
因此 TSM **无法**让空闲服的 Private 回落。已做的：

- 空闲整理日志改为同时打印 `工作集→工作集` 与 `私有→私有`，把这件事变得可见（提交 `e326703`）

**可选方案（需决策）**：

1. **接受现状**：1.0GB/服是大图上界，只影响内存预算，不影响稳定性；
2. **加一个极小插件**（如 `/tsmgc`：`GC.Collect(2,Forced,compacting) + EmptyWorkingSet`），
   由 TSM/Bot 在低峰对空服触发 → 立即回落到 ~540MB（需把该插件加入各服清单）；
3. 由现有插件（如 FixTools / PGameAPI）增加一个等价命令 —— 归 RPG/生存侧。
