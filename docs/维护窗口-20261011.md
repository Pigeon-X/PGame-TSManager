### 四、⚠ 顺带发现（真问题，已修未部署）：TSM 的「停止」是**硬杀**，不落盘

- 代码：`IsRunning = false` 原来是 `process.Kill(true)` —— 直接杀进程；
- 证据 1：**每一轮启动的日志第一行**都是 `TShock被强制关闭。建议使用exit指令进行正常安全关闭。`；
- 证据 2：10-10 `23:43:48 → 10-11 00:57` 那一轮（3.5 小时）日志里**一次保存都没有** → 00:57 的换版重启等于把这 3.5 小时里未落盘的地形改动全丢了；
- 证据 3：直播服世界文件 mtime 在我手动 `/save` 之前是 **00:32:36**（距当时 41 分钟）→ 停服时未落盘。

**修法（已实现、本地构建 0 错误，随下一个 exe 上）**：停止改为
`/save`（先保证落盘）→ `/off`（TShock 保存后自行退出）→ 最多等 12 秒 → 仍在才 `Kill(true)`；
异步执行不阻塞 UI，`_userStopRequested` 已置位所以看门狗不会误当崩溃；
`StopForExit`（退出 TSM 时）原来发的 `/stop` 也一并改成 `/save` + `/off`。

**链路已实测**（01:13 用 0 号直播服，0 人在线，测完立即拉回）：

| 动作 | 结果 |
|---|---|
| `POST /command {"command":"/save"}` | 200，日志 `SaveManager: INFO: 世界已经保存到(…\鸽子直播服.wld)`，世界 mtime → **01:14:00** |
| `POST /command {"command":"/off"}` | 200，进程 **3 秒内自行退出**（无需强杀）；TSM 显示 `stopped` 且**没有**自动拉起（手动停止语义正确） |
| 重新 `start` | 01:14:16 起来；**新日志中「被强制关闭」命中 0 条**（此前每一轮都有）→ 证明 `/off` 是干净关服 ✅ |

> ⇒ 结论：`/save` + `/off` 这条优雅链路可用且有效；TSM 的停止/重启/换版从此不再丢世界。
