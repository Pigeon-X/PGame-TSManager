# TShock 6.2.1 控制台/退出行为分析（C 方案进展）

日期：2026-10-05
目标：查清「从 PGame-TSManager（GUI 父进程）启动的服务器约 40 秒后以退出码 0 自行退出」的根因。

## 已确认的事实

1. **TShock 自己的输入钩子不会因 EOF 退出**

   `TerrariaApi.Server.Hooking.ServerHooks::Main_ReadLineInput` 的 IL：

   ```
   IL_0000: ldarg.1
   IL_0001: ldc.i4.0
   IL_0002: stfld ReadLineInputEventArgs::ContinueExecution   // = false
   IL_0007: br.s IL_0010
   IL_0009: ldc.i4.s 100
   IL_000B: call Thread::Sleep(100)          <-- 读到 null 就睡 100ms
   IL_0010: call Console::ReadLine()
   IL_0015: dup
   IL_0016: stloc.0
   IL_0017: brfalse.s IL_0009                <-- null 就回去 sleep 再读（死循环等待）
   IL_0019: ... 把输入交给 HookReturnValue
   IL_0020: ret
   ```

   ⇒ 官方已经处理了「没有输入」的情况：会一直轮询等待。
   **所以「stdin EOF 导致退出」这个假设不成立。**

2. **真正的服务器主循环在 `Terraria.Main::mfwh_DedServ`（OTAPI.dll）**

   里面调用 `Terraria.Main::ReadLineInput()` 的地方有 10+ 处（菜单、选世界、输密码、主循环）。
   主循环回跳断言：
   ```
   IL_0BB2: ldloc.s V_6
   IL_0BB4: brtrue IL_009b      // V_6 为真 -> 回到循环开头
   ```

3. **可疑点：`Console::Clear()` / 其它 Console 属性**

   `mfwh_DedServ` 里多处调用 `Console::Clear()`（IL_0BA3 / IL_0BD8 等），
   这些**在没有真实控制台时会抛 IOException**（IL 里确实有 try/catch，但只包了一部分）。
   还有 `Console::WriteLine` / `Console::Write` 大量直接调用。
   ⇒ 高度怀疑：GUI 父进程下没有真实控制台，某处 Console 调用抛异常/返回异常值，
   让主循环的 V_6 变成「该退出」，于是**干净退出（exit 0）**。

## 结论（阶段性）

- 「TShock 因 stdin EOF 自杀」= **错**，别往这个方向修。
- 方向应改为：**让子进程一定拥有真实控制台**，或**补丁掉对 Console 的强依赖**。
- 已验证：有真实控制台的宿主（cmd / PowerShell / WMI 创建 cmd）启动时，服务器可以长期稳定运行。
  GUI（WPF）父进程没有控制台，子进程拿不到 ⇒ 会退。

## 工具

`maintenance/tools/TShockConsoleProbe`：Mono.Cecil 写的 IL 探针。

```powershell
# 找 Console.* / Environment.Exit 的调用点
dotnet TShockConsoleProbe.dll <OTAPI.dll> <TerrariaServer.dll> <TShockAPI.dll>

# dump 某个方法整段 IL
dotnet TShockConsoleProbe.dll <OTAPI.dll> Terraria.Main::mfwh_DedServ

# dump 某个方法的 IL 区间
dotnet TShockConsoleProbe.dll <OTAPI.dll> Terraria.Main::mfwh_DedServ 0B70 0C20
```
