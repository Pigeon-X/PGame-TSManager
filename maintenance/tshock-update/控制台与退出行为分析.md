# TShock 6.2.1「启动约 40 秒后静默 exit 0」根因分析（已定位到具体代码）

日期：2026-10-05
状态：**根因已确认**（有 IL + 抓到的真实异常为证）

---

## 一、结论速览

**不是 TShock 的问题，也不是单纯的控制台问题，是「插件抛出异常 + TShock 报错本身又抛异常」的双重故障：**

```
插件业务异常（SQLite 迁移 / NRE）
   ↓ 插件 catch 后调用 TShock.Log.ConsoleError(...) 想报告
TShockAPI.TextLog.ConsoleError 里  Console.ForegroundColor = ConsoleColor.Red;
   ↓ 进程没有真实控制台 → 这个 setter 抛 System.IO.IOException
IOException 逃出插件 catch
   ↓
Terraria.Main.DedServ() 抛出
   ↓ Terraria.Program.mfwh_orig_RunGame 的 catch 吞掉
Program.DisplayException(e) → 又往控制台写 → 同样失败
   ↓
方法正常 ret → 一路返回 → TShock.Server.exe 返回 0    ★“静默 exit 0”
```

**为什么有控制台就没事**：有控制台时 `Console.ForegroundColor` 正常，插件异常被正常记日志，服务器继续跑。

## 二、证据

### 1) IL 证据：异常被吞

`Terraria.Program::mfwh_orig_RunGame`
```
IL_00A5: callvirt void Terraria.Main::DedServ()          // 服务器主循环
IL_00AB: callvirt void Terraria.Server.Game::Run()
IL_00B0: leave.s IL_00C3
IL_00B2: call void Terraria.Program::DisplayException(Exception)   // ★ 吞掉
IL_00B7: leave.s IL_00C3
IL_00C3: ret
```

### 2) 排除「stdin EOF」

`TerrariaApi.Server.Hooking.ServerHooks::Main_ReadLineInput`
```
IL_0009: Thread::Sleep(100)
IL_0010: Console::ReadLine()
IL_0017: brfalse.s IL_0009     // null 就睡 100ms 再读，无限等待
```
→ 官方已处理没输入的情况，EOF 不会导致退出。

### 3) 真实异常（用探针插件抓到）

`maintenance/tools/ExceptionProbePlugin`（订阅 `FirstChanceException` 写文件）抓到：

```
System.NullReferenceException
   at TShockData.BossProgress.GetKillCount(Int32 npcNetId) in PGameAPI.dll     ← 成百次

Microsoft.Data.Sqlite.SqliteException: SQLite Error 1: 'duplicate column name: PlayerId'
Microsoft.Data.Sqlite.SqliteException: SQLite Error 1: 'duplicate column name: ProjId'
```

### 4) 致命的 Console 调用（TShockAPI 源码）

`TShockAPI/TextLog.cs`：
```csharp
public void ConsoleError(string message)
{
    Console.ForegroundColor = ConsoleColor.Red;      // ★ 无控制台 -> IOException
    Console.WriteLine(message);
    Console.ForegroundColor = ConsoleColor.Gray;
    Write(message, TraceLevel.Error);
}
```
`ConsoleWarn` / `ConsoleInfo` 同样。

## 四、正确的修法（建议按顺序做）

### ① 修插件 bug（治本，属 bot / RPG 会话范围）
- `PGameAPI.dll` → `TShockData.BossProgress.GetKillCount(int npcNetId)` 空引用
  （初始化早于数据加载，取不到就应返回 0 而不是 NRE）
- `TSWeb` 的 `AntiCheatLog.sqlite` 迁移重复加列
  （`ALTER TABLE ... ADD COLUMN PlayerId` 应先查 `PRAGMA table_info`）

这两个不修，任何宿主下都会不断抛异常。

### ② 让 TShock 的报错不再自杀
把 `TextLog.Console*` 以及其它 Console 属性调用全部包 try/catch
（或整体改为 `if (Console.IsOutputRedirected) 跳过颜色`）。

### ③ 给子进程真实控制台（最省事）
`PGame-TSManager` 启动服务器时，用能分配新控制台的方式：
- `cmd.exe /c start "" /b <exe> ...`（cmd 会拿到控制台，子进程继承）
- 或 CreateProcess 带 `CREATE_NEW_CONSOLE` 后立刻 `ShowWindow(SW_HIDE)`

实测：用这种方式启动，服务器可长期稳定运行（远程三服就是这么跑的）。
