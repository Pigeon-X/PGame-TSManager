# TShock 6.2.1 启动即退出（exit 0）根因分析

日期：2026-10-05
现象：从 PGame-TSManager（WPF，无控制台）启动服务器，约 40 秒后进程消失，**退出码 0**，日志无任何异常。
结论：**不是正常关服，是启动期异常被吞掉。**

## 一、完整调用链（从 IL 反出）

```
TShock.Server.exe                     ← 只是 launcher（TShockLauncher/Program.cs）
  └─ TerrariaApi.Server.Program.Main(args)          （TerrariaServerAPI）
       ├─ ServerApi.Hooks.AttachOTAPIHooks(args)
       ├─ StartServer(args) -> Terraria.WindowsLaunch.Main(args)   （OTAPI）
       │     ├─ SetConsoleCtrlHandler(ConsoleCtrlCheck, true)
       │     └─ Terraria.Program.LaunchGame(args,false)
       │           └─ Program.RunGame()
       │                 └─ Program.mfwh_RunGame()
       │                       ├─ Program.LaunchOTAPI()
       │                       ├─ Program.orig_RunGame()
       │                       │     └─ Program.mfwh_orig_RunGame()   ★关键
       │                       └─ Program.ShutdownOTAPI()
       └─ ServerApi.DeInitialize()
```

`Terraria.Program.mfwh_orig_RunGame` 的 IL：

```
IL_009D: ldsfld bool Terraria.Main::dedServ
IL_00A2: brfalse.s IL_00AA
IL_00A4: ldloc.0
IL_00A5: callvirt void Terraria.Main::DedServ()      // ★ 服务器主循环
IL_00AA: ldloc.0
IL_00AB: callvirt void Terraria.Server.Game::Run()
IL_00B0: leave.s IL_00C3                             // try 结束
IL_00B2: call void Terraria.Program::DisplayException(Exception)   // ★ 异常被吞
IL_00B7: leave.s IL_00C3
IL_00C3: ret
```

⇒ **`DedServ()` / `Run()` 抛出的任何异常都会被 catch → `DisplayException` → 然后方法正常 `ret`。**
⇒ 外层一路 return，`TShock.Server.exe` 返回 0。**这就是“干净退出 0”的真相。**

## 二、被推翻的假设

- ❌「stdin EOF 导致退出」—— 错。
  证据：`TerrariaApi.Server.Hooking.ServerHooks::Main_ReadLineInput` 的 IL：
  ```
  IL_0009: Thread::Sleep(100)
  IL_0010: Console::ReadLine()
  IL_0017: brfalse.s IL_0009      // null 就睡 100ms 再读，无限等待
  ```
  官方已经处理了没有输入的情况。

## 三、为什么 TShock 日志里看不到异常

`Program.DisplayException` 只往**控制台**写。GUI 父进程下没有控制台 → 什么都没留下。
（TShock 的日志文件 `Logs\<日期>.log` 只记录它自己的日志器，记录不到这里。）

## 四、下一步：把被吞的异常抓出来

工具已备好：`maintenance/tools/TShockExceptionPatch`

作用：给 `Terraria.Program::DisplayException` 打补丁，在方法开头插入
```
File.AppendAllText(AppContext.BaseDirectory + "server-start-exception.log", e.ToString() + "\r\n");
```
这样无论有没有控制台，异常都会落到文件里。

用法：
```powershell
dotnet TShockExceptionPatch.dll <某服的 bin\OTAPI.dll>
```

> 注意：`OTAPI.dll` 常被残留进程占用，打补丁前必须确保所有 TShock / 管理器进程都已退出
> （必要时重启机器），否则报 `file is being used by another process`。

拿到异常内容后，就能确定是哪一个 Console 调用 / 哪一段启动逻辑抛的，
再决定：
- 用 Mono.Cecil 把该调用包 try/catch（根治，所有宿主都能跑），或
- 用带真实控制台的宿主拉起（变通）。

## 五、已确认的稳定宿主

| 宿主 | 有真实控制台 | 结果 |
| --- | --- | --- |
| cmd / PowerShell / WMI 创建 cmd | ✅ | 长期稳定运行 |
| WPF（PGame-TSManager）直接创建子进程 | ❌ | 约 40 秒后 exit 0 |

## 六、工具清单

| 工具 | 作用 |
| --- | --- |
| `maintenance/tools/TShockConsoleProbe` | Mono.Cecil IL 探针：查 `Console.*` / `Environment.Exit` 调用点、dump 指定方法 IL |
| `maintenance/tools/TShockExceptionPatch` | 给 `DisplayException` 打补丁，把被吞异常写进 `server-start-exception.log` |
