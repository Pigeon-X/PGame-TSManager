# PGame-TSManager 服务器管理操作说明

## 日常启动

1. 双击 `PGame-TSManager.exe`，只会显示管理器窗口。
2. 下拉框选择服务器，查看运行状态和在线人数。
3. 单服维护时使用「启动本服」或「停止本服」。
4. 日常开服使用「全部启动（顺序）」，管理器会等待上一台端口就绪后再启动下一台。
5. 点击窗口右上角关闭时，按提示选择缩小到托盘或退出；退出会再次确认。

## 发管理员指令

在底部输入框输入中文或英文指令，回车发送给当前服务器；按钮「全部发送」会发送给所有运行中的服务器。
指令会自动补 `/`，例如输入 `help` 等同于 `/help`。`/help` 由 TShock 原始指令处理，管理器不覆盖。

## 插件管理

点击「插件开关」选择本服从总插件库加载的插件，保存后可选择重启本服。

- 插件本体放根目录 `Plugins`。
- 插件依赖放根目录 `bin`。
- 每服加载清单只写在 `1.PigeonServers\<服务器>\config.json`。
- 修改插件后必须重启对应服务器，不能在玩家在线时直接覆盖正在加载的 DLL。

## 配置边界

服务器配置位于 `1.PigeonServers\<服务器>\tshock`，世界和数据库属于运行数据。
管理器启动前会备份关键配置；管理器本身不会自动重写 TShock 配置。

TShock 更新使用 `maintenance\tshock-update` 的独立流程，不从管理器界面执行。

## 故障处理

- 服务器异常退出：看门狗默认等待 8 秒自动重启，连续 3 次后停止并上报。
- 启动失败：先看管理器面板和 `Logs`，再运行 `PGame-TSManager.exe --selfcheck`。
- REST 无法发指令：检查该服 `tshock\config.json` 的 REST 端口和令牌字段「用户名 / 用户组」。
- 配置汉化检查：运行 `maintenance\tools\Test-TShockConfig.ps1`。
- TShock 更新失败：使用 `Backups\tshock-update-时间戳` 回滚核心文件，再按顺序启动。

## 固定维护顺序

Git 提交 → 构建 → 远程源测试端部署 → 可见重启 → 三服端口和插件验证 → 同步桌面镜像 → 测试群上报。
